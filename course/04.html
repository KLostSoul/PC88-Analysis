4부의 범위: 여기서는 특정 게임의 대사를 찾거나 D88의 원본 sector까지 역추적하지 않습니다. 먼저 디버거라는 관찰 도구를 제대로 사용하는 법에 집중합니다. 실제 data와 disk의 출처를 끝까지 이어 가는 방법은 다음 단계에서 다룹니다.
화면 결과에서 실행 원인으로

1. 게임을 그냥 보는 것과 게임이 왜 그렇게 움직였는지 분석하는 것은 다르다

게임을 플레이할 때는 화면에 나타난 결과만 보면 됩니다. 분석할 때는 그 결과를 만든 CPU의 동작을 거꾸로 찾아야 합니다.

플레이어가 보는 것

HP 10 → 공격받음 → HP 09

결과가 보이면 충분합니다.

분석할 때 묻는 것

  • 10이라는 값은 어디에 있었는가?
  • 어느 instruction이 그 값을 읽었는가?
  • 어느 instruction이 1을 감소시켰는가?
  • 09를 어느 memory에 다시 썼는가?
  • 그 순간 PC와 register는 어떤 값이었는가?
왜 이 질문이 필요한가? 화면은 최종 결과만 보여 줍니다. 게임 내부 구조를 찾으려면 결과를 만든 실행 과정을 관찰해야 합니다.
프로그램을 멈춰서 본다

2. 디버거는 실행 중인 프로그램을 원하는 순간에 멈추고 내부 상태를 관찰하는 도구다

CPU는 게임이 실행되는 동안 instruction을 계속 처리합니다. 정상 속도로 실행되고 있는 상태에서는 PC와 register 값이 빠르게 바뀌기 때문에 사람이 특정 순간의 상태를 읽기 어렵습니다. 그래서 필요한 순간에 실행을 멈추고 그 시점의 상태를 조사할 수 있어야 합니다.

LD
PC=8000h
INC
PC=8003h
CALL
PC=8004h
WRITE
PC=8120h
STOP
JR
아직 실행 전
이제 이름을 붙이면: 이런 관찰 기능을 제공하는 도구를 Debugger라고 합니다. 특정 사건에서 자동으로 멈추는 기능은 Breakpoint, instruction을 하나씩 실행하는 기능은 Single-step이라고 부릅니다. 문자 기반으로 명령을 입력하고 상태를 확인하는 환경은 흔히 Monitor라고 부르기도 합니다.
흔한 오해: Debugger가 게임의 정답이나 routine의 역할을 자동으로 알려 주는 것은 아닙니다. Debugger는 PC·register·memory·실행 code 같은 증거를 보여 주고, 그 증거의 의미를 해석하는 것은 분석하는 사람의 일입니다.
정적 분석과 동적 분석

3. Code를 읽을 수 있어도 “실제로 그렇게 실행됐는지” 확인하려면 디버거가 필요하다

2부에서 Z80 assembly를 읽는 법을 배웠습니다. 그래서 아래 code의 가능한 동작은 읽을 수 있습니다. 하지만 이것만으로는 이 code가 실제 게임에서 언제 실행됐고, 실행 당시 값이 무엇이었는지까지는 알 수 없습니다.

LD A,(9000h)
DEC A
LD (9000h),A

정적으로 읽으면

9000h의 값을 A로 읽고, 1 감소한 뒤 다시 9000h에 쓴다는 것을 알 수 있습니다.

실행 중에 멈추면

PC = 8123h
A  = 0Ah
RAM[9000h] = 0Ah

실제 값과 실제 실행 위치를 확인할 수 있습니다.

4. 왜 실제 PC-88 대신 에뮬레이터 디버거를 사용하는가

실제 PC-88에도 N88-BASIC의 machine-language monitor처럼 memory와 machine code를 살펴볼 수 있는 기능이 있었습니다. 하지만 이 강좌에서는 실행 중인 게임을 원하는 순간에 멈추고, PC와 register를 확인하고, 특정 주소의 실행이나 memory READ/WRITE를 감시하며, 같은 상태를 반복해서 살펴봐야 합니다.

이런 실습을 쉽게 반복하기 위해 PC-88 에뮬레이터의 debugger를 사용합니다.

5. PC-88 에뮬레이터는 여러 종류가 있으므로 강좌의 원리를 특정 프로그램 명령에 고정하지 않는다

6. 이 강좌에서는 여러 에뮬레이터 가운데 QUASI88을 실제 조작 예시로 사용한다

7. 디버거를 열었을 때 처음 해야 할 일은 명령을 외우는 것이 아니라 “어디에 무엇이 보이는지” 파악하는 것이다

GUI debugger라면 register·disassembly·memory가 각각 창으로 나뉠 수 있고, monitor 방식이라면 명령을 입력해 필요한 정보를 출력합니다. 모양은 달라도 우리가 찾아야 할 정보는 같습니다.

Disassembly현재 PC 주변에 어떤 Z80 instruction이 있는지 봅니다.
