## 5부에서 재사용한 실제 관찰

- 첫 단서: 작은 「夢幻戦士」 표시 시점의 `PC=04DAh`, `RR (HL)` 반복.
- step·dump: `04CBh INC HL`, `04CCh RR (HL)`; 정지 시 `HL=D8DFh`, 첫 step 후 `HL=D8E0h`, 다음 step 후 `D8E0h: 10h → 08h`.
- 호출자: `03E6h CALL 05ADh`는 disasm에서 확인한 호출 후보. `05ADh` breakpoint에서의 실제 실행 직전 호출은 `026Eh CALL 05ADh`.
- 공통 처리: `05ADh`는 5Ch·5Dh·5Eh 세 plane에서 `061Fh`를 호출. 같은 실행에서 `HL'=4405h` 입력 후보, `HL=C50Eh` 출력 후보 관찰.
- 제외한 후보: `D400h` WRITE 시 `6344h LDIR`가 넓은 영역에 `00h`을 반복 기록하므로 GVRAM plane 초기화로 분류.
- **미확인 범위:** `4405h` 이후 전체 데이터 범위와 최종 화면의 완전한 대응을 확정한 실측 결과로 사용하지 않음.

5부 실제 QUASI88 원문 로그 10개는 [5부 HTML](05.html)의 해당 단계 안에 있습니다.

## 6부에서 재사용한 실제 관찰

- 첫 단서: 대기 루프의 `PC=04BDh`, `HL=96A3h`, `SP=00FAh`.
- Stack: `00FAh: D0 18 4F 04`, 저장된 `DE=18D0h` 다음의 반환 주소 `044Fh`.
- 호출·Script: `0443h CALL 0B8Fh`, `044Fh JP 02E4h`, `02EDh LD E,(HL)`.
- 문자값: RAM `969Fh: B8 62 C8 18 48 38`는 「雨」「が」「や」.
- 출력: `0B8Fh` 문자 출력, `0BE1h` Kanji ROM 읽기 시작, `0BFEh` 글리프 기록 직전. 해당 명령의 step 후에도 일반 RAM dump에 이전 값 `FFh`가 보여 메모리 접근 종류를 구분해야 함.
- RAM 수정: `969Fh: B8 62 → C8 18`로 첫 글자가 「が」가 되어 화면이 「ががやん」으로 시작.
- ROM 수정: `KANJI1.ROM`의 「雨」 글리프 `C560h~C57Fh` 32바이트를 「가」 모양으로 바꾸자 원본 Script에서 첫 글자가 「가」로 출력됨.
- **미확인 범위:** Script가 원본 D88의 어느 Sector에서 왔는지와 ROM 전체 파일 크기의 전후를 보여 주는 별도 실측은 확보하지 않음.

## 실측 사례와 점검 지침 구분

7부에서 설명하는 'RAM 수정이 반영되지 않았을 때' 또는 'ROM을 바꾸어도 출력이 같을 때'의 점검 순서는 **일반적인 재조사 지침**입니다. 기존 5·6부에서 그런 실패를 새로 실측했다는 뜻이 아닙니다. 최종 독립 과제는 두 강좌의 첫 관찰 정보만 먼저 제공한 뒤 실제 원문과 비교하도록 구성했습니다.

외부 기술 문서는 PC-88·Z80·QUASI88의 설명을 추가로 확인해야 하는 경우에만 참고합니다. 다른 플랫폼의 강좌 구성이나 실측 자료를 이 강좌의 근거로 대체하지 않습니다.
