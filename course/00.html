bit와 논리 — 모든 데이터의 가장 작은 출발점

1-1. bit는 두 상태 중 하나를 나타낸다

bit는 binary digit의 줄임말입니다. 논리적으로는 0 또는 1이라는 두 상태 가운데 하나를 나타냅니다. 전자회로에서는 이 상태를 전압 범위 등의 물리적인 방법으로 구현하지만, 프로그램을 배우는 단계에서는 0과 1이라는 추상적인 상태로 이해하면 됩니다.

주의: bit는 정보의 단위입니다. “트랜지스터 하나가 bit 하나다”처럼 물리 부품 수와 1:1로 외우면 실제 회로 구조와 맞지 않습니다.

1-2. bit가 늘어나면 가능한 조합이 두 배씩 늘어난다

bit 수가능한 패턴 수부호 없는 정수로 해석할 때
1 bit2¹ = 20 ~ 1
2 bit2² = 40 ~ 3
4 bit2⁴ = 160 ~ 15
8 bit2⁸ = 2560 ~ 255
16 bit2¹⁶ = 65,5360 ~ 65,535

8 bit = 1 byte입니다. 그래서 1byte는 256개의 서로 다른 bit 패턴을 가질 수 있습니다. 그 패턴을 숫자로 해석할지, 문자 코드로 해석할지, 명령어로 해석할지는 그 데이터를 사용하는 방식에 따라 달라집니다.

1-3. 2진수와 16진수는 같은 값을 다르게 적는 방법이다

컴퓨터 내부의 bit를 그대로 쓰면 길어지기 때문에 역분석에서는 16진수를 매우 자주 사용합니다. 4bit는 16가지 패턴을 가지므로 16진수 한 자리와 정확히 대응합니다.

왜 16진수를 쓰면 편할까?
CPU가 16진수로 계산하기 때문은 아닙니다. 컴퓨터 내부에서는 결국 0과 1의 bit로 값이 저장됩니다. 16진수가 편한 가장 큰 이유는 2진수와 정확히 4bit 단위로 끊어 읽을 수 있기 때문입니다.

예를 들어 8bit 한 byte는 2진수로 0000 0000 ~ 1111 1111처럼 8자리를 써야 하지만, 16진수로는 00h ~ FFh처럼 항상 두 자리면 됩니다. 16bit 값도 2진수로는 16자리가 필요하지만 16진수로는 0000h ~ FFFFh처럼 네 자리로 표현할 수 있습니다.

더 중요한 것은 자리의 경계가 byte와 정확히 맞는다는 점입니다. 16진수 한 자리 = 4bit, 두 자리 = 8bit = 1byte이므로 A5h를 보면 바로 1010 0101₂로 나눠 볼 수 있습니다. 반대로 2진수 1111 1111₂도 4bit씩 1111 / 1111로 끊으면 곧바로 F / F, 즉 FFh가 됩니다.

10진수도 같은 값을 표현할 수 있지만 bit 경계와 자릿수가 직접 대응하지 않습니다. 예를 들어 255만 보고는 각 bit가 어떻게 켜져 있는지 바로 알기 어렵지만, FFh는 두 자리 모두 1111이라는 것을 바로 알 수 있습니다. 그래서 메모리 주소, opcode, byte 데이터, bit mask를 읽고 비교하는 역분석에서는 16진수가 훨씬 다루기 쉽습니다.

1-8. 게임에서는 bit를 어떻게 쓰는가

한 byte의 각 bit를 여러 상태 표시로 사용할 수 있습니다. 예를 들어 아래는 설명을 위한 가상의 상태 byte입니다.

bit 0 = 대화 중
bit 1 = 무적 상태
bit 2 = 보스전
bit 3 = 메뉴 열림
bit 4~7 = 다른 상태

특정 bit만 검사하거나 켜고 끄는 데 AND, OR, XOR 같은 bit 연산이 쓰입니다. 이후 Z80의 AND, OR, XOR, BIT, SET, RES 명령과 연결됩니다.

register — CPU 안에서 바로 사용하는 작은 저장 공간

2-1. 왜 register가 필요한가

CPU가 계산할 때마다 RAM까지 가서 값을 읽고 다시 쓰기만 한다면 명령을 처리하기 불편합니다. 그래서 CPU 안에는 현재 계산에 필요한 값, 주소, 실행 위치, 상태 등을 바로 보관하는 작은 저장 공간이 있습니다. 이것이 register(레지스터)입니다.

비유: RAM이 번호가 붙은 큰 서랍장이라면 register는 작업대 위에 놓인 작은 칸입니다. 서랍장에는 많은 것을 보관할 수 있지만, 지금 손에 들고 계산하는 값은 작업대 위에 놓는다고 생각하면 됩니다.
중요: 모든 register가 똑같은 역할을 하는 것은 아닙니다. B·C·D·E·H·L처럼 비교적 자유롭게 쓰는 register도 있고, PC·SP·I·R처럼 CPU 동작과 직접 연결된 특별한 register도 있습니다. 또한 “HL은 주소용”처럼 외우면 안 됩니다. HL은 16bit 값을 담는 register이고, Z80 명령어에 HL을 주소처럼 사용하는 형태가 특히 많기 때문에 메모리 포인터로 자주 보이는 것입니다.

2-3. A — Accumulator: 계산의 중심이 되는 8bit register

A는 Accumulator(누산기)입니다. Z80의 많은 8bit 산술·논리 명령이 A를 중심으로 동작합니다. 값을 더하거나 빼고, AND·OR·XOR를 하고, 값을 비교하거나 I/O로 주고받을 때 A가 자주 등장합니다.

LD A,05h      ; A에 05h를 넣음
ADD A,03h     ; A = 05h + 03h = 08h
AND 0Fh       ; A와 0Fh를 AND한 결과가 다시 A에 들어감
CP 08h        ; A와 08h를 비교하고 결과 상태는 F에 기록

따라서 디버거에서 A=41h라고 보이면 “CPU가 지금 41h라는 8bit 값을 A라는 작업 register에 들고 있다”고 읽으면 됩니다.

2-4. F — Flags: 방금 한 연산의 결과 상태를 기억한다

F는 일반적인 숫자를 보관하기 위한 register라기보다, 연산 결과가 어떤 상태였는지 표시하는 여러 flag bit를 모아 둔 register입니다. 예를 들어 결과가 0이 되었는지, 자리올림이 생겼는지 같은 정보를 다음 명령이 확인할 수 있습니다.

초보 단계에서 먼저 기억할 것은 Z와 C입니다. 예를 들어 CP 08h로 A와 08h를 비교한 뒤 두 값이 같으면 Z flag가 1이 되고, 이어지는 JR Z,... 같은 조건 분기가 그 상태를 이용합니다.

AF라는 표기도 있습니다. A와 F를 합쳐 AF라는 16bit 쌍처럼 PUSH/POP하거나 보조 세트와 교환할 수 있습니다. 하지만 BC·DE·HL처럼 일반적인 16bit 계산용 register pair로 생각하면 안 됩니다.

2-5. B, C, D, E, H, L — 자유롭게 쓰되 명령어마다 자주 맡는 일이 있다

이 여섯 개는 Z80의 general-purpose register(범용 register)입니다. 즉 “B에는 반드시 반복 횟수만 넣어야 한다”처럼 고정된 용도가 있는 것은 아닙니다. 필요하면 각각 독립적인 8bit 값 하나를 저장할 수 있습니다. 다만 Z80 명령어 자체가 특정 register를 특별하게 사용하는 경우가 있어 실제 프로그램에서는 자연스럽게 자주 맡는 역할이 생깁니다.

register크기초보자가 이해할 역할Z80에서 특히 자주 보이는 사용
B8 bit일반적인 8bit 값 보관DJNZ 명령이 B를 1 감소시키고 0이 아니면 반복하므로 반복 횟수(counter)로 자주 보입니다. BC의 상위 byte이기도 합니다.
C8 bit일반적인 8bit 값 보관BC의 하위 byte입니다. IN r,(C), OUT (C),r 형태에서는 I/O port 주소 지정에 BC가 사용되므로 C가 port 번호 쪽으로 자주 보입니다.
D8 bit일반적인 8bit 값 보관DE의 상위 byte입니다. D 단독에는 “반드시 이것”이라는 고정 역할은 없지만 DE를 주소로 쓸 때 상위 8bit를 담당합니다.
E8 bit일반적인 8bit 값 보관DE의 하위 byte입니다. DE가 메모리 목적지 주소를 가리킬 때 하위 8bit를 담당합니다.
H8 bit일반적인 8bit 값 보관HL의 상위 byte입니다. HL=9000h이라면 H에는 90h가 들어갑니다.
L8 bit일반적인 8bit 값 보관HL의 하위 byte입니다. HL=9000h이라면 L에는 00h가 들어갑니다.

2-6. BC, DE, HL — 8bit 두 개를 묶어서 16bit로 사용한다

B와 C, D와 E, H와 L은 각각 두 개를 묶어 16bit register pair로 사용할 수 있습니다. 왼쪽 register가 상위 byte, 오른쪽 register가 하위 byte입니다.

pair실제 코드에서 자주 맡는 역할대표 예
BC개수·반복 횟수 또는 16bit 일반 값으로 자주 쓰입니다. Z80의 block transfer/search 명령에서는 남은 byte 수를 BC가 관리합니다.LDIR에서 BC가 0이 될 때까지 복사를 반복합니다.
DE목적지(destination) 주소로 자주 쓰입니다. 특히 block transfer 명령이 HL에서 읽은 데이터를 DE가 가리키는 곳에 씁니다.LDIR: (HL) → (DE)
HL메모리 주소(pointer)로 매우 자주 쓰입니다. Z80 명령어에는 (HL) 형태의 메모리 간접 접근이 풍부합니다.LD A,(HL)은 HL이 가리키는 RAM의 byte를 A로 읽습니다.
 
; 메모리 8000h~80FFh의 256byte를 9000h~90FFh로 복사하는 전형적인 형태
LD HL,8000h    ; source 주소
LD DE,9000h    ; destination 주소
LD BC,0100h    ; 복사할 byte 수 = 256
LDIR           ; (HL) → (DE), HL/DE 증가, BC 감소를 반복
이 예가 아주 중요합니다. “HL=source, DE=destination, BC=count”는 Z80의 block transfer 명령에서 실제로 정해진 역할입니다. 하지만 다른 코드에서는 HL·DE·BC에 전혀 다른 값을 넣어 사용할 수도 있습니다.

2-7. PC — Program Counter: CPU가 어느 명령을 실행할지 가리킨다

PC는 Program Counter입니다. CPU가 메모리에서 다음 opcode를 가져올 주소를 유지합니다. 명령 byte를 읽으면 PC가 다음 위치로 진행하고, JP, JR, CALL, RET 같은 흐름 제어 명령을 실행하면 PC가 다른 주소로 바뀝니다.

PC = 8000h

→

2-8. SP — Stack Pointer: stack의 현재 꼭대기 주소를 가리킨다

SP는 Stack Pointer입니다. stack은 별도의 마법 같은 저장 장치가 아니라 RAM의 일부이고, SP가 그 stack의 현재 top 위치를 주소로 가리킵니다.

→
RAM EFFEh...

Z80의 PUSH와 CALL은 SP를 낮은 주소 방향으로 움직이며 stack에 값을 넣고, POP과 RET는 값을 꺼내면서 SP를 다시 높은 주소 방향으로 움직입니다. 자세한 동작은 7장 stack에서 실제 주소로 다시 확인합니다.

2-9. IX와 IY — Index Register: 기준 주소 + 작은 이동값으로 메모리에 접근한다

LD IX,9000h
LD A,(IX+05h)  ; 9005h의 byte를 A에 읽음

게임에서는 캐릭터 상태 구조체, 테이블, 여러 필드가 일정 간격으로 배치된 데이터 등을 다룰 때 이런 방식이 유용합니다. 다만 “IX는 캐릭터 전용”처럼 정해진 용도는 없습니다.

2-10. I — Interrupt Vector Register: 인터럽트 처리 주소를 만드는 데 사용한다

I는 8bit Interrupt Vector Register입니다. 특히 Z80의 Interrupt Mode 2(IM 2)에서 인터럽트가 발생했을 때 사용할 vector table 주소를 만드는 데 I가 상위 8bit로 사용됩니다.

초보 단계에서는 “I는 일반 계산용 register가 아니라 인터럽트 처리용 주소 체계에 참여하는 특수 register”라고 기억하면 충분합니다. PC-88 게임 코드를 보다가 LD I,A 또는 LD A,I를 만나면 일반적인 HL 포인터와 같은 용도로 해석하면 안 됩니다.

2-11. R — Memory Refresh Register: DRAM refresh를 돕는 특수 register

R은 8bit Memory Refresh Register입니다. Z80은 명령 opcode를 fetch하는 과정에서 R의 하위 7bit를 자동으로 증가시키고, 이 값을 DRAM refresh 주소 생성에 이용합니다. 따라서 프로그램이 마음대로 쓰는 일반-purpose counter와는 성격이 다릅니다.

R을 단순한 “시간 register”로 외우면 안 됩니다. 일부 프로그램이 R 값을 읽어서 난수성이나 타이밍에 활용하기도 하지만, 본래 목적은 메모리 refresh 지원입니다.

2-12. A′F′, B′C′, D′E′, H′L′ — 보조 register 세트

Z80에는 A·F·B·C·D·E·H·L과 같은 크기의 두 번째 register 세트가 하나 더 있습니다. 이름에 작은 따옴표를 붙여 A′, F′, B′처럼 적습니다.

A F / BC DE HL
현재 사용 중
⇄
A′ F′ / BC′ DE′ HL′
보조 세트

EX AF,AF′는 AF와 AF′를 교환하고, EXX는 BC·DE·HL과 BC′·DE′·HL′를 한꺼번에 교환합니다. 빠른 인터럽트 처리처럼 기존 register 값을 stack에 하나씩 저장했다가 복원하는 시간을 줄이고 싶을 때 유용합니다.

보조 register는 평소에 LD B′,10h처럼 직접 이름을 지정해 접근하는 방식이 아닙니다. 주 세트와 교환해서 현재 세트로 만든 뒤 사용한다는 점이 핵심입니다.

3-3. 16bit address와 64 KiB 논리 주소 공간

16bit로는 0000h ~ FFFFh의 65,536가지 주소를 표현할 수 있습니다. 각 주소가 1byte 위치를 가리키는 byte-addressed 공간이라면 총 65,536 byte = 64 KiB의 논리 주소 범위를 갖습니다.

PC-88에서 중요한 예고: CPU의 주소가 16bit라는 사실과 컴퓨터에 존재하는 모든 RAM·ROM·VRAM의 물리적 총량은 같은 말이 아닙니다. PC-88에서는 메모리 선택과 뱅크 전환, VRAM 접근 같은 구조를 따로 배우게 됩니다.

4-2. Fetch → Decode → Execute

CPU의 동작을 개념적으로 단순화하면 명령을 가져오고(Fetch), 뜻을 해석하고(Decode), 실행한다(Execute)는 반복으로 볼 수 있습니다.

정확성 보충: Fetch → Decode → Execute는 이해를 위한 개념 모델입니다. 실제 Z80 명령은 opcode와 operand의 길이, memory/I/O access, machine cycle에 따라 여러 세부 동작과 timing을 거칩니다. 모든 명령이 정확히 세 번의 물리 단계로 끝난다는 뜻은 아닙니다.

4-3. PC — 실행 위치를 가리키는 Program Counter

Z80의 PC는 현재 가져올 명령의 16bit 주소를 유지합니다. 명령 byte를 읽으며 다음 위치로 진행하고, jump나 CALL 같은 명령이 실행되면 새로운 주소로 바뀝니다.

PC = 8000h
      │
      ▼
8000h : 21 00 90   ← CPU가 여기서 명령을 읽기 시작
8003h : 3E 05
8005h : 77

그래서 디버거에서 PC=02ED를 확인한다는 것은 실행 흐름의 현재 위치를 잡는다는 뜻입니다. 역분석에서 PC는 “지금 어느 코드가 실행되는가”를 추적하는 핵심 좌표입니다.

4-4. CPU가 명령과 데이터를 구분하는 방법

메모리에는 결국 byte가 들어 있습니다. 어떤 byte를 CPU가 PC를 통해 명령으로 fetch하면 machine instruction으로 해석되고, 프로그램이 단순 데이터로 읽으면 숫자·문자·그래픽 등의 데이터가 됩니다. 메모리의 byte 자체에 “나는 코드”라는 딱지가 붙어 있는 것은 아닙니다.

machine language — CPU가 직접 해석하도록 정의된 명령 형식

5-1. opcode와 operand

CPU마다 어떤 byte 패턴을 어떤 명령으로 해석할지가 정해져 있습니다. 명령의 종류를 나타내는 부분을 opcode, 명령이 사용할 값이나 주소 같은 추가 정보를 operand라고 부릅니다.

3E05→LD A,05h
byte역할

이 명령을 실행하면 A register에는 05h가 들어갑니다.

5-2. 명령은 길이가 모두 같지 않다

Z80 명령은 1byte짜리도 있고, operand나 prefix가 붙어 여러 byte가 되는 명령도 있습니다. 따라서 역어셈블할 때는 “한 byte = 한 명령”이라고 생각하면 안 됩니다.

210090→LD HL,9000h

즉 사람이 보는 16bit 값은 9000h이지만 명령 byte 안에서는 00 90 순서로 나타납니다.

5-4. 같은 byte도 문맥에 따라 코드일 수도 데이터일 수도 있다

hex editor에서 21 00 90을 발견했다고 해서 무조건 LD HL,9000h라고 결론 내릴 수 없습니다. CPU가 그 위치를 실행 흐름으로 가져오면 명령이지만, 프로그램이 문자열이나 테이블의 일부로 읽으면 데이터입니다.

역분석의 기본 원칙: byte 패턴만 보고 코드·데이터를 확정하지 않습니다. 실행 추적, 참조하는 코드, 주변 데이터 구조를 함께 확인합니다.

stack — RAM의 일부를 LIFO 방식으로 사용하는 구조

7-1. LIFO: Last In, First Out

stack은 마지막에 넣은 값이 가장 먼저 나오는 LIFO 구조입니다. 접시를 쌓은 뒤 위에서부터 다시 꺼내는 모습을 떠올리면 됩니다.

SP=F000h · stack 비어 있음

이 체험은 LIFO 개념을 보기 쉽게 1byte 단위로 표시합니다. 실제 Z80의 PUSH qq는 16bit register pair를 저장합니다.

SP → F000h

Z80의 SP(Stack Pointer)는 RAM 안에 놓인 stack의 현재 top을 가리키는 16bit register입니다. Z80에서 PUSH는 SP를 감소시키며 데이터를 저장하므로 stack은 낮은 주소 방향으로 자랍니다.

8000h  21 00 90    LD HL,9000h   → HL = 9000h
8003h  3E 05       LD A,05h       → A  = 05h

bit / byte

21, 00, 90은 각각 1byte입니다.

register

HL과 A가 CPU 내부 작업 값으로 사용됩니다.

RAM / address

9000h가 RAM의 위치를 가리키고 그곳의 값이 05h로 바뀝니다.

CPU

PC가 opcode를 차례로 fetch하고 명령을 실행합니다.

machine language

CPU는 byte 패턴을 Z80 명령 규칙으로 해석합니다.

assembler

LD HL,9000h 같은 source를 해당 byte로 변환할 수 있습니다.

stack

이 코드가 subroutine 안에 있다면 호출자의 return address가 stack에 있을 수 있습니다.

확인 문제

Q1. 8bit는 몇 가지 서로 다른 bit 패턴을 만들 수 있는가?
2⁸ = 256가지입니다.
Q2. A5h를 2진수로 쓰면?
A = 1010, 5 = 0101이므로 1010 0101입니다.
Q3. 주소 9000h에 값 41h가 있다. 9000h와 41h는 각각 무엇인가?
9000h는 address, 41h는 그 address에 저장된 value입니다.
Q4. HL=9000h이고 RAM[9000h]=41h라면 HL과 (HL)은?
HL은 9000h, (HL)은 41h입니다.
Q5. F register는 왜 필요한가?
산술·논리 연산 결과의 상태를 flag bit로 남겨 조건 분기 등의 다음 동작에서 사용할 수 있게 합니다.
Q5-1. B register가 반복 횟수로 자주 보이는 이유는?
Z80의 DJNZ 명령이 B를 자동으로 1 감소시키고, B가 0이 아니면 지정한 위치로 분기하기 때문입니다. 하지만 B가 항상 반복 횟수 전용인 것은 아닙니다.
Q5-2. HL=9000h일 때 H와 L에는 각각 무엇이 들어 있는가?
H는 상위 byte 90h, L은 하위 byte 00h입니다.
Q5-3. LDIR에서 HL, DE, BC는 각각 어떤 역할을 하는가?
HL은 source 주소, DE는 destination 주소, BC는 남은 byte 수를 담당합니다. 복사할 때마다 HL과 DE는 증가하고 BC는 감소합니다.
Q5-4. IX와 IY가 HL과 다른 대표적인 장점은?
(IX+d), (IY+d)처럼 기준 주소에 signed 8bit displacement를 더해 구조체나 테이블의 여러 필드에 접근하기 쉽다는 점입니다.
Q5-5. I와 R은 일반-purpose register인가?
아닙니다. I는 주로 IM 2 인터럽트 vector 주소 형성에, R은 DRAM refresh 지원에 쓰이는 특수 register입니다.
Q6. Fetch → Decode → Execute는 무엇을 뜻하는가?
명령을 가져오고, 어떤 명령인지 해석하고, 실제 동작을 수행한다는 CPU 실행의 개념적 흐름입니다.
Q7. 21 00 90에서 00 90 순서가 나오는 이유는?
9000h의 16bit operand가 low byte 00h, high byte 90h 순서로 인코딩되기 때문입니다.
Q8. assembly language와 assembler의 차이는?
assembly language는 사람이 작성하는 저수준 언어이고, assembler는 그 source를 machine/object code로 번역하는 프로그램입니다.
Q9. disassembler가 원래 주석과 변수명을 그대로 복구하지 못하는 이유는?
최종 machine code에는 원래 source의 많은 이름과 주석, 고수준 의미가 남아 있지 않기 때문입니다.
Q10. Z80에서 PUSH 후 SP는 어느 방향으로 이동하는가?
낮은 address 방향으로 이동합니다. 16bit PUSH에서는 SP가 총 2 감소합니다.
Q11. CALL이 stack을 사용하는 핵심 이유는?
subroutine이 끝난 뒤 원래 실행 위치로 돌아가기 위한 return address를 보관하기 위해서입니다.
Q12. D88 파일 오프셋과 RAM address는 같은 숫자 체계인가?
아닙니다. D88 파일 내부 위치와 CPU가 보는 RAM address는 서로 다른 좌표이며 loader/sector 구조를 통해 대응 관계를 찾아야 합니다.
