1. PC-88은 어떤 컴퓨터인가

1-1. ‘PC-88’은 한 대의 컴퓨터 이름이 아니다

PC-88이라는 말은 보통 NEC의 PC-8801 계열을 통칭합니다. 초대 PC-8801은 1981년 12월 출하되었고, 이후 1980년대 말까지 여러 후속 모델이 나왔습니다. 따라서 “PC-88 사양은 이것이다”라고 한 줄로 말하기 어렵습니다. 기본 구조는 이어지지만 CPU 속도, RAM, FDD, 사운드, 한자 ROM, 확장 슬롯, 화면 기능 등이 세대마다 달라졌기 때문입니다.

1-2. 8비트 컴퓨터라는 말은 무엇을 뜻하나

PC-8801의 메인 CPU는 Z80 계열입니다. 여기서 “8비트 컴퓨터”라는 표현은 단순히 RAM이 8비트라는 뜻이 아닙니다. Z80은 기본적인 데이터 처리 단위가 8bit이고 A, B, C 같은 주요 범용 register도 8bit입니다. 반면 주소를 다룰 때는 HL, DE, BC, PC, SP 같은 16bit 값을 사용하므로 0000h~FFFFh의 64KiB 논리 주소 공간을 표현할 수 있습니다.

0부와 연결: 0부에서 “8bit 값”과 “16bit address”를 따로 배운 이유가 여기서 드러납니다. PC-88의 Z80은 8bit 데이터를 주로 처리하지만, 메모리 위치를 가리킬 때는 16bit 주소를 사용합니다.

1-3. 당시 일본 PC는 서로 호환되는 하나의 표준이 아니었다

오늘날의 PC처럼 “어느 회사 컴퓨터를 사도 같은 Windows 프로그램을 실행한다”는 식으로 생각하면 안 됩니다. 1980년대 일본의 개인용 컴퓨터 시장에는 NEC PC-88, Sharp X1, Fujitsu FM 계열 등 서로 다른 하드웨어가 공존했습니다. 같은 게임도 각 기종에 맞춰 별도 이식판이 나오는 경우가 많았고, 화면 방식과 음원, 디스크 형식, CPU까지 달랐습니다.

왜 한글화에서 중요한가? “같은 게임의 다른 기종판에 대사가 있으니 PC-88판도 같은 위치겠지”라고 생각하면 안 됩니다. 게임의 내용은 같아도 데이터 배치와 출력 엔진은 기종별 하드웨어에 맞게 완전히 다를 수 있습니다.

2. PC-8801과 mkII — 기본 구조와 디스크의 정착

2-1. 초대 PC-8801에서 이미 64KB RAM과 48KB GVRAM을 갖고 있었다

초대 PC-8801의 표준 Main RAM은 64KB, 그래픽용 GVRAM은 48KB였습니다. 이 두 숫자를 합쳐 “112KB RAM”이라고 이해하면 안 됩니다. Main RAM은 CPU가 프로그램과 일반 데이터를 처리하는 작업 공간이고, GVRAM은 화면 그래픽을 저장하기 위한 별도 메모리입니다. 역할과 접근 방법이 다릅니다.

Main RAM 64KB

게임의 코드, 변수, 디스크에서 읽어 온 데이터, 임시 작업 영역 등 일반 프로그램이 사용하는 RAM입니다.

GVRAM 48KB

화면에 표시할 그래픽 정보를 보관하는 별도 메모리입니다. 나중에 Blue/Red/Green plane으로 나누어 설명합니다.

2-2. 그런데 공식 사양에는 최대 576KB라고 적혀 있다

여기서 초보자가 바로 혼란을 느낄 수 있습니다. “표준 RAM은 64KB인데 최대 사용자 메모리가 576KB라면 Z80은 576KB 주소를 어떻게 쓰는가?”라는 의문입니다. 답은 bank switching입니다. 추가 메모리를 장착할 수는 있지만, Z80의 16bit 주소 자체가 19bit나 20bit로 늘어나는 것은 아닙니다. 필요한 추가 RAM의 일부를 현재 64KiB 주소 공간 안에 창(window)처럼 연결해서 사용합니다.

아직 여기서는 구조만 기억: “메모리를 더 꽂는다”와 “CPU 주소 범위가 늘어난다”는 서로 다른 이야기입니다. 이 차이를 6장과 7장에서 그림으로 자세히 풉니다.

2-3. 초기 기종에는 한자와 사운드도 지금 생각하는 ‘기본 기능’이 아니었다

초대 PC-8801의 NEC 공식 사양에서 한자 기능과 사운드는 옵션으로 기록되어 있습니다. 즉 후대 PC-88 게임에서 자연스럽게 보는 FM 음악과 한자 출력 환경을 초기 기종까지 그대로 거슬러 올라가 적용하면 안 됩니다. PC-88 계열은 시간이 지나며 “게임에 필요한 기능”이 점차 기본 사양으로 들어온 플랫폼입니다.

2-4. PC-8801mkII에서 FDD가 본체 안으로 들어온다

1983년의 PC-8801mkII는 CPU 4MHz, Main RAM 64KB, GVRAM 48KB라는 기본 틀을 유지하면서 5인치 2D FDD를 본체에 넣은 모델을 제공했습니다. 여기서 중요한 것은 “플로피라는 저장장치가 새로 발명됐다”가 아니라, 디스크 기반 소프트웨어를 쓰기 편한 본체 구성이 정착하기 시작했다는 점입니다.

3. PC-8801mkIISR — 왜 PC-88 게임의 기준점이 되는가

1985년 1월의 PC-8801mkIISR은 PC-88 게임사를 이해할 때 매우 중요한 전환점입니다. NEC 공식 사양상 메인 CPU는 여전히 4MHz이고 Main RAM도 64KB, GVRAM도 48KB입니다. 숫자만 보면 초대 PC-8801과 비슷해 보입니다. 그러나 실제로는 화면 모드, 팔레트, GVRAM 접근, 텍스트 처리, FM 음원이 크게 강화됐습니다.

3-1. “사양표의 MHz만 보면 안 된다”는 첫 사례

초대 PC-8801과 SR의 CPU clock이 모두 4MHz라고 해서 두 기종의 실제 동작 환경이 같다는 뜻은 아닙니다. CPU가 같은 속도로 명령을 실행하더라도, 화면 메모리에 접근하는 방식이나 전용 하드웨어가 달라지면 프로그램이 해야 하는 일이 줄어들거나 특정 작업을 더 효율적으로 처리할 수 있습니다.

초기 PC-8801

4MHz CPU. 초기 화면·메모리 구조를 사용합니다.

mkIISR

CPU는 4MHz지만 High-speed TVRAM, 확장된 GVRAM 접근, Graphics ALU, V2 palette, FM 음원 등이 추가됩니다.

핵심: “CPU clock = 컴퓨터 전체 성능”이 아닙니다. 같은 4MHz라도 CPU 주변의 메모리와 화면 하드웨어가 바뀌면 게임이 체감하는 환경이 달라질 수 있습니다.

3-2. N, V1, V2는 왜 있는가

컴퓨터가 발전하면 새 기능을 쓰고 싶지만, 기존 소프트웨어도 계속 실행되어야 합니다. 그래서 PC-88 계열에는 세대 호환을 위한 여러 mode가 존재합니다. 입문 단계에서는 다음처럼 이해하면 충분합니다.

3-3. V1S와 V1H는 또 무엇인가

SR 이후 자료나 에뮬레이터 설정에서 V1S, V1H를 보게 됩니다. 같은 V1이라도 standard/high-speed 조건이 구분됩니다. I/O 자료의 mode sense에는 V1/V2와 high-speed 상태가 따로 존재하고, High-speed TVRAM은 V1H/V2에서 사용할 수 있습니다.

V1S
V1의 standard-speed 쪽 환경으로 이해하면 됩니다.
V1H
V1 호환성을 유지하면서 high-speed 쪽 메모리 동작을 사용하는 환경입니다.

3-4. 512색이라는 말은 512색을 동시에 보여 준다는 뜻이 아니다

V2의 대표적인 특징 중 하나가 아날로그 RGB palette입니다. 흔히 “512색”이라고 쓰지만, 대표적인 V2 컬러 화면은 512가지 후보색 중 palette에 선택한 8색을 사용하는 방식입니다. “512색 중 8색”과 “512색 동시 표시”는 전혀 다른 의미입니다.

비유: 큰 색연필 상자에 512가지 색이 있지만, 지금 책상 위에 올려놓고 동시에 쓰는 펜은 8개라고 생각하면 됩니다. palette를 바꾸면 그 8개의 선택을 다른 색으로 바꿀 수 있습니다.

3-5. SR에서 사운드가 게임 플랫폼의 중요한 기본 기능이 된다

SR의 NEC 공식 사양에는 FM 3음 + SSG 3음이 기본 기능으로 들어갑니다. 초기 기종처럼 사운드를 옵션으로만 생각하는 시대와 달리, 게임 제작자가 FM 음원을 전제로 음악을 구성할 수 있는 기반이 마련된 것입니다. 이후 Sound Board II 계열에서 다시 한 번 크게 확장됩니다.

왜 이 강좌가 SR 이후를 기준으로 하나? 후기 PC-88 게임에서 자주 만나는 V2 화면, FM 음원, 고속 텍스트 RAM, 확장된 GVRAM 접근 같은 요소가 SR을 기준으로 본격화되기 때문입니다.

4. 후기 모델은 무엇이 달라졌나 — 모델명을 외우지 말고 ‘변화의 축’을 본다

후기 PC-88을 이해할 때 가장 나쁜 학습법은 모델명을 연도순으로 외우기만 하는 것입니다. 한글화와 역분석에서 필요한 것은 어느 세대부터 CPU, RAM, FDD, 사운드, 한자 ROM, 확장 슬롯이 달라지는지입니다. 같은 게임이라도 이 차이에 따라 실행 조건이나 사용할 수 있는 하드웨어가 달라질 수 있습니다.

4-1. F 계열과 M 계열을 비교하면 후기 구조가 보인다

FR/MR, FH/MH, FA/MA처럼 비슷한 시기에 F와 M이 짝으로 등장하는 경우가 있습니다. 모든 세부를 모델명의 한 글자로 단정할 수는 없지만, 실제 사양을 보면 M 계열이 대체로 더 많은 RAM과 2HD FDD를 갖는 상위 구성입니다.

세대F 계열M 계열중요한 차이

4-2. MR — “표준 RAM 192KB”가 등장한다

PC-8801mkIIMR의 NEC 공식 사양은 표준 RAM을 192KB로 기록합니다. 이것은 192KB가 Z80 주소 공간에 한 줄로 펼쳐졌다는 뜻이 아닙니다. Main RAM 64KB + Expanded RAM 128KB로 이해해야 합니다. 이 128KB는 32KB짜리 bank 네 개로 나누어 선택해서 접근합니다. 6장에서 이 구조를 천천히 설명합니다.

4-3. FH / MH — CPU가 실제로 8MHz와 4MHz를 전환한다

FH와 MH에서는 CPU가 8MHz/4MHz 전환을 지원합니다. 여기서 처음으로 앞에서 말한 SR의 “high-speed memory 환경”과 CPU clock 자체의 8MHz화를 구분해야 합니다. 오래된 소프트웨어의 timing을 맞추기 위해 4MHz mode도 유지됩니다.

역분석에서 왜 중요한가? 어떤 게임이 단순 loop 횟수로 시간을 맞추거나 특정 기종 timing을 가정하면 4MHz/8MHz 설정에 따라 속도가 달라질 수 있습니다. 에뮬레이터에서 CPU clock 설정을 무심코 바꾸면 게임 동작 자체가 달라지는 이유입니다.

4-4. FA / MA — 사운드가 다시 크게 확장된다

FA/MA 세대의 공식 사양에는 FM 6음, Rhythm 6음, SSG 3음, ADPCM이 기록되어 있고, Sound RAM 256KB도 존재합니다. 여기서 Sound RAM 256KB는 Main RAM과 같은 일반 작업 RAM이 아닙니다. ADPCM 등 사운드 기능을 위한 별도 메모리입니다.

MA의 예: Main RAM 64KB + Expanded RAM 128KB + GVRAM 48KB + Sound RAM 256KB …

이 숫자를 전부 더해서 “Z80이 직접 한꺼번에 쓸 수 있는 RAM”이라고 계산하면 안 됩니다. 메모리마다 역할과 접근 경로가 다릅니다.

4-5. FE / FE2가 64KB라고 해서 시대를 거꾸로 간 것은 아니다

후기에는 보급형과 상위형이 나뉩니다. FE/FE2는 표준 RAM 64KB의 보급형 성격이고, MA2/MC 같은 상위형은 192KB RAM과 더 많은 기능을 유지합니다. 따라서 “연도가 늦을수록 RAM 숫자가 무조건 커진다”라는 단순한 발전표로 보면 안 됩니다.

그리고 FE와 FE2는 RAM 용량은 둘 다 64KB이지만 CPU가 Main RAM을 읽고 쓰는 조건까지 완전히 같은 것은 아닙니다. NEC의 FE2 사양에는 CPU 항목에 Main Memory Access No-Wait가 따로 명시되어 있습니다. 이 표현을 이해하려면 먼저 wait state가 무엇인지 알아야 합니다.

4-6. Main Memory Access No-Wait — CPU가 RAM을 기다리지 않는다는 뜻

CPU와 RAM은 항상 똑같은 속도로 움직이는 것이 아닙니다. CPU가 메모리 주소를 내보내고 “이 주소의 값을 읽겠다”라고 요청하면 RAM은 그 주소의 데이터를 준비해서 CPU에 돌려줘야 합니다. 그런데 CPU가 다음 동작으로 넘어가야 하는 순간까지 RAM이 값을 준비하지 못했다면 어떻게 해야 할까요? CPU가 그대로 진행하면 아직 준비되지 않은 잘못된 값을 읽을 수 있습니다.

이때 하드웨어는 CPU에게 잠깐 기다리라는 신호를 줄 수 있습니다. Z80에서는 이것이 WAIT 신호이고, CPU가 추가로 기다리는 한 단계를 wait state라고 부릅니다. Z80 자체도 메모리 read/write cycle 중 WAIT 신호를 받아 필요한 만큼 동작을 늘릴 수 있도록 설계되어 있습니다.

WAIT가 필요한 경우

CPU가 메모리에 접근했지만 메모리나 주변 회로가 아직 준비되지 않았습니다.

CPU 동작 → WAIT → 데이터 준비 → 계속

즉 CPU clock은 8MHz여도 메모리 접근 때 중간에 기다리는 시간이 들어갈 수 있습니다.

No-Wait인 경우

Main RAM이 CPU가 요구하는 timing 안에 데이터를 준비할 수 있어 추가 wait state를 넣지 않습니다.

CPU 동작 → 데이터 준비 → 바로 계속

같은 8MHz CPU라도 Main RAM 접근에서 기다림이 없다면 실제 프로그램 실행이 더 효율적일 수 있습니다.

CPU가 8MHz라는 말과 No-Wait는 같은 뜻이 아니다

8MHz는 CPU의 기본 clock 속도를 말합니다. 반면 No-Wait는 CPU가 Main RAM에 접근할 때 추가 대기 시간을 넣지 않는다는 뜻입니다. 따라서 두 기종이 모두 8MHz라고 적혀 있어도 메모리 접근 조건이 다르면 실제 실행 timing은 완전히 같다고 단정할 수 없습니다.

초보자가 기억할 한 문장: 8MHz는 CPU가 얼마나 빠른가를 말하고, Main Memory Access No-Wait는 그 CPU가 Main RAM을 사용할 때 중간에 추가로 기다리지 않아도 된다는 뜻입니다.
역분석에서 왜 중요한가? 게임의 delay loop, 화면 갱신, 복사 routine처럼 실행 시간에 민감한 코드를 볼 때는 CPU clock만 보고 속도를 판단하면 부족할 수 있습니다. 같은 8MHz 계열이라도 memory wait 조건이 다르면 실제 명령 실행에 걸리는 시간이 달라질 수 있기 때문입니다. 특히 emulator에서 기종을 바꾸거나 timing 문제를 확인할 때 이런 차이를 알고 있어야 합니다.

4-7. MC — PC-8801 계열의 말기

1989년의 PC-8801MC는 표준 RAM 192KB, GVRAM 48KB, Sound RAM 256KB, 2D/2HD FDD를 갖고 있으며 model2에는 CD-ROM drive가 들어갑니다. CPU는 8MHz/4MHz이고 공식 사양에는 FE2와 마찬가지로 Main Memory Access No-Wait가 명시됩니다. 따라서 MC의 8MHz를 앞선 8MHz 모델과 단순히 숫자만 같은 것으로 보면 안 되고, Main RAM 접근 조건까지 함께 봐야 합니다.

5. PC-88 안에는 왜 이렇게 많은 RAM과 ROM이 있는가

PC-88 자료를 처음 보면 Main RAM, Expanded RAM, Text VRAM, GVRAM, Sound RAM, BASIC ROM, KANJI ROM 같은 이름이 한꺼번에 나옵니다. 모두 “byte를 저장한다”는 공통점은 있지만 무엇을 저장하고, 누가 읽고 쓰며, 어떻게 접근하는지가 다릅니다. 한글화에서 이 구분을 못 하면 주소를 찾고도 엉뚱한 메모리를 고치게 됩니다.

Main RAM
CPU의 일반 작업 공간. 게임 코드, 변수, 디스크에서 읽어온 data, 임시 buffer 등이 놓일 수 있습니다.
Expanded RAM
Main RAM 외에 추가된 작업 RAM. 32KB bank를 0000h~7FFFh에 연결해 선택 접근합니다.
System ROM
N88-BASIC/N-BASIC 등 시스템 프로그램이 들어 있는 ROM. 설정에 따라 0000h~7FFFh 쪽에 보일 수 있습니다.
GVRAM
그래픽 화면의 pixel 정보를 보관합니다. 대표적인 컬러 화면에서는 B/R/G 3 plane으로 구성됩니다.
Text VRAM
텍스트 화면 표시를 위한 메모리 계통. 세대에 따라 High-speed TVRAM 같은 구조도 추가됩니다.
KANJI ROM
문자 코드가 아니라 글자의 점 모양(bitmap glyph)을 저장한 ROM입니다.
Sound RAM
FA/MA 등 강화 음원 세대의 ADPCM 처리 등에 쓰이는 별도 메모리입니다. Main RAM이 아닙니다.

5-1. 왜 메모리를 하나로 합치지 않았나

오늘날의 컴퓨터도 RAM, VRAM, firmware ROM, GPU memory 등이 역할에 따라 나뉩니다. 당시 8비트 PC에서는 CPU 주소가 16bit로 제한되어 있었고 화면·음원 같은 장치의 요구도 달랐기 때문에, 각 기능에 맞는 메모리를 별도로 두고 I/O port와 bank switching으로 필요한 순간에 연결하는 구조가 흔했습니다.

“RAM 용량 합계” 오해: Main RAM 64KB + Expanded RAM 128KB + GVRAM 48KB + Sound RAM 256KB라고 해서 CPU가 00000h~7BFFFh 같은 하나의 연속 주소로 이들을 보는 것이 아닙니다.

6. 192KB RAM은 어떻게 쓰는가 — 왜 32KB씩 bank를 바꾸는가

이 장은 후기 PC-88을 이해하는 핵심입니다. MR, MH, MA, MA2, MC 같은 M 계열의 “표준 RAM 192KB”를 단순히 큰 서랍 하나로 생각하면 뒤의 디버깅이 전부 헷갈립니다. 먼저 숫자를 분해해 봅니다.

Main RAM 64KB + Expanded RAM 128KB = 표준 RAM 192KB

6-1. Z80은 주소를 16bit만 가지고 있다

Z80의 주소는 16bit이므로 0000h부터 FFFFh까지 총 65,536개의 byte 위치, 즉 64KiB만 한 번에 표현할 수 있습니다. 물리적으로 RAM을 더 장착해도 CPU의 address register가 갑자기 17bit나 18bit로 늘어나지는 않습니다.

6-2. 그래서 Expanded RAM의 일부를 64KiB 안에 ‘창’처럼 끼워 넣는다

PC-88의 Expanded RAM 하드웨어는 선택된 확장 RAM을 CPU 주소 0000h~7FFFh에 연결할 수 있습니다. 이 범위의 크기를 계산해 보면:

7FFFh - 0000h + 1 = 8000h bytes = 32KiB

즉 “32KB씩 읽는다”는 말은 임의의 숫자를 정한 것이 아니라, PC-88의 확장 RAM이 CPU 주소 공간의 하위 절반인 0000h~7FFFh를 하나의 bank window로 사용하도록 설계되어 있기 때문입니다.

비유: Z80 앞에 64칸짜리 책장이 하나 있다고 생각합시다. 창고에는 책이 더 많지만 책장을 늘릴 수는 없습니다. 대신 책장의 아래 32칸을 통째로 비우고 “창고의 묶음 A”, “묶음 B”를 번갈아 꽂아 넣습니다. CPU는 항상 같은 0~31번 칸을 보지만, 스위치를 바꾸면 그 뒤에 있는 실제 책 묶음이 달라집니다.

6-5. E2h와 E3h는 각각 무엇을 하는가

Expanded RAM은 I/O port E2h와 E3h로 제어합니다. 여기서는 Z80 명령 자체를 외울 필요는 없고 역할만 구분합니다.

Port역할쉽게 말하면
E2h0000h~7FFFh의 read/write를 Expanded RAM으로 보낼지 제어“확장 RAM 창을 실제로 사용할 것인가?”
E3h어느 expansion card의 어느 32KB bank를 선택할지 지정“창 뒤에 어느 서랍을 연결할 것인가?”
E3h로 bank를 고른다. 예: Card 0의 Bank 2.
E2h로 read/write를 허용한다. 그러면 CPU의 0000h~7FFFh 접근이 선택한 Expanded RAM으로 향합니다.
CPU는 평소처럼 0000h~7FFFh를 읽고 쓴다. CPU 입장에서는 별도의 18bit 주소를 만드는 것이 아닙니다.
다른 data가 필요하면 bank를 다시 바꾼다. 주소는 같지만 연결되는 물리 RAM이 달라집니다.

6-6. E3h에 card 번호까지 있는 이유

E3h는 bank 번호뿐 아니라 card 번호도 선택할 수 있습니다. 하드웨어 제어 자체는 여러 128KB 확장 카드가 존재하는 경우까지 고려합니다. 한 card 안에 32KB bank가 네 개 있으므로:

1 card = 4 banks × 32KiB = 128KiB

Card 0~3까지 선택할 수 있는 구조라면 제어 방식 자체는 최대 4 × 128KB = 512KB의 Expanded RAM을 구분할 수 있습니다. 다만 실제로 장착 가능한 양은 모델의 확장 슬롯 수와 내장 RAM 구성에 따라 달라집니다.

초대 PC-8801

확장 슬롯 4개, 공식 최대 사용자 메모리 576KB. 64KB Main RAM에 최대 512KB 추가라는 계산과 맞아떨어집니다.

M 계열

내장 Expanded RAM 128KB가 Card 0 역할을 하고, 모델의 슬롯 구성에 따라 추가 확장이 제한됩니다. 예를 들어 MR/MH/MA의 공식 최대 사용자 메모리는 448KB입니다.

6-7. 왜 64KB 전체를 bank로 바꾸지 않고 32KB만 바꾸는가

확인 가능한 사실은 PC-88 Expanded RAM 회로가 0000h~7FFFh의 하위 32KB를 bank window로 사용한다는 것입니다. “NEC가 반드시 이런 철학 때문에 32KB를 골랐다”는 설계 의도까지 단정해서는 안 됩니다. 다만 동작상 결과는 이해할 수 있습니다.

  • 하위 32KB만 Expanded RAM으로 바꾸고, 상위 주소 영역은 다른 작업에 계속 사용할 수 있습니다.
  • 프로그램은 32KB 단위로 data를 교체하면서도 나머지 주소 공간을 유지할 수 있습니다.
  • 64KB 전체를 매번 통째로 갈아치우는 것보다 현재 실행 code·stack·buffer를 남겨 둔 채 추가 data bank에 접근하기 쉬운 구조가 됩니다.
한글화 연결: 번역문이나 font data가 Expanded RAM에 적재되는 게임을 분석할 때는 “주소”만 기록해서는 부족합니다. 그 순간의 E2h/E3h 상태, 즉 어느 card/bank가 선택됐는지도 함께 기록해야 같은 data를 다시 찾을 수 있습니다.

8-4. Independent access와 Extended access

가장 이해하기 쉬운 방식은 5Ch~5Eh로 plane 하나를 선택하는 independent access입니다. SR 이후에는 port 35h와 Graphics ALU를 사용하는 extended access도 있어서 세 plane을 동시에 다루거나 논리 연산을 이용할 수 있습니다.

1부에서 여기까지만: extended access의 bitfield와 ALU 명령까지 외울 필요는 없습니다. “게임이 화면을 그릴 때 항상 Blue → Red → Green을 하나씩 직접 쓰는 것만은 아니며, SR 이후에는 그래픽 전용 하드웨어를 이용할 수 있다” 정도만 이해하면 됩니다.

8-5. CRTC는 무엇을 하는가

CRTC(CRT Controller)는 화면의 텍스트 표시 타이밍과 형식 등을 제어하는 장치입니다. PC-88 I/O map에서 50h/51h가 CRTC 제어에 사용됩니다. 쉽게 말하면 “화면에 어떤 memory를 어떤 timing과 행/열 구조로 보여 줄 것인가”를 관리하는 쪽의 하드웨어입니다.

8-6. ‘CPU가 쓰는 VRAM’과 ‘모니터에 표시되는 화면’도 같은 말이 아니다

Port 53h에서는 Text screen과 GVRAM plane의 표시 여부를 제어할 수 있습니다. 따라서 CPU가 어느 VRAM에 data를 쓰고 있다는 사실과, 그 plane이 지금 화면에 실제 표시되고 있다는 사실은 구분해야 합니다.

예: GVRAM에 byte를 정상적으로 썼는데 화면에서 변화가 안 보인다면, write가 실패한 것뿐 아니라 현재 display enable 상태나 mode가 다른 것도 원인일 수 있습니다.

8-7. 게임의 글자는 Text 화면이 아니라 GVRAM에 그려질 수 있다

특히 게임의 대화창이나 큰 일본어 글꼴, 장식된 문자는 Text VRAM의 문자 셀을 사용하는 대신 font bitmap을 가져와 GVRAM에 직접 그리는 경우가 있습니다. 이때 화면에서 “あ”를 봤다고 해서 VRAM에 ASCII/JIS 코드 “あ”가 그대로 들어 있는 것이 아닙니다. GVRAM에는 이미 점 그림이 들어 있습니다.

Sound

10. 사운드는 왜 모델별로 따로 알아야 하는가

문자 한글화가 목적이라도 사운드 구조를 완전히 빼면 안 됩니다. 후기 PC-88 게임은 음악뿐 아니라 ADPCM 음성, 효과음, sound interrupt를 사용하고, 게임 code가 sound hardware를 제어합니다. 특히 음성이 나오는 이벤트 장면을 분석할 때는 대사 출력과 sound timing이 서로 얽힐 수 있습니다.

10-1. 초기 기종 — 사운드는 기본 전제가 아니었다

초대 PC-8801과 mkII 시기의 공식 사양에서는 사운드가 옵션 중심입니다. 따라서 이 시기 소프트웨어를 볼 때 후기의 FM chip이 항상 존재한다고 가정하면 안 됩니다.

10-2. SR — FM 3음 + SSG 3음이 기본이 된다

SR에서 FM 3음 + SSG 3음이 기본 기능으로 들어오면서 PC-88 게임 음악의 대표적인 음색이 만들어집니다. 이후 FR/MR 계열도 이 기본 구성을 이어갑니다.

10-3. FH/MH — 기본 구성과 Sound Board II 확장을 구분한다

FH/MH의 NEC 기본 사양은 FM3 + SSG3입니다. 그러나 이 세대는 Sound Board II 계열 확장을 사용할 수 있는 구조가 마련되어 있습니다. 따라서 “FH/MH = 처음부터 모든 OPNA 기능이 기본 내장”이라고 단순화하면 부정확합니다.

10-4. FA/MA — 강화 음원이 기본 사양으로 들어온다

FA/MA의 공식 사양에는 FM 6음 + Rhythm 6음 + SSG 3음 + ADPCM이 기록되어 있습니다. 또한 Sound RAM 256KB가 있습니다. 이 메모리는 ADPCM data 등 사운드 기능을 위한 것으로 Main RAM과 구분해야 합니다.

10-5. 왜 ‘Sound RAM 256KB’를 Main RAM에 더하면 안 되나

Sound RAM은 Z80이 일반 변수처럼 아무 주소에서나 쓰는 Main RAM의 연장이 아닙니다. sound chip의 ADPCM 기능을 통해 접근하는 별도 memory입니다. 따라서 MA에 “192KB + 256KB = 448KB Main RAM”이 있다고 말하면 틀립니다.

비유: Main RAM이 CPU 작업 책상이라면 Sound RAM은 녹음기에 들어 있는 전용 테이프 보관함에 가깝습니다. 둘 다 data를 저장하지만 사용하는 장치와 접근 방법이 다릅니다.

10-6. 한글화에서 사운드가 문제되는 실제 상황

  • 음성과 자막 timing을 맞춰야 하는 이벤트
  • sound interrupt가 text 출력 routine과 실행 시간을 나눠 쓰는 경우
  • ADPCM data와 문자열 data가 같은 disk block/loader 경로 주변에 있는 경우
  • Sound Board II 존재 여부에 따라 code path가 갈라지는 경우
1부의 범위: 여기서는 세대별 음원 차이만 이해합니다. YM2203/YM2608 register와 port programming은 필요한 실제 분석 편에서 다룹니다.
Disk Subsystem

11. 플로피는 Main CPU가 직접 sector를 읽는 단순 장치가 아니다

11-1. PC-88의 FDD 쪽에는 별도의 subsystem이 있다

PC-88의 5인치 FDD 계통은 Main CPU와 별도로 동작하는 disk subsystem을 갖습니다. Main CPU가 플로피의 자기 표면에 직접 명령을 내려 sector byte를 하나씩 가져오는 구조로 생각하면 안 됩니다. SUB 쪽에는 별도의 CPU, ROM/RAM, FDC가 있고 Main 쪽과 인터페이스를 통해 데이터를 주고받습니다.

11-2. Main과 SUB는 무엇을 주고받나

I/O map에서 FCh~FFh는 disk subsystem interface의 8255 계통 port로 정리되어 있습니다. Main 쪽과 SUB 쪽 사이에는 data와 handshake signal이 오갑니다. 쉽게 말하면 “명령을 보냈는가?”, “data를 받을 준비가 되었는가?”, “이 data가 유효한가?”, “받았는가?”를 서로 확인하면서 전송합니다.

Main이 SUB에 작업을 요청한다. 어떤 disk operation이 필요한지 command를 전달합니다.
SUB가 FDC와 drive를 제어한다. 실제 floppy sector를 읽는 물리적인 처리는 SUB 쪽에서 담당합니다.
SUB가 읽은 data를 Main 쪽으로 넘긴다. 8255 interface와 handshake를 통해 전달합니다.
Main code가 그 data를 원하는 RAM buffer로 옮긴다. 그 뒤 게임의 parser나 decompressor, text routine 등이 사용합니다.

11-3. 그래서 D88 offset과 RAM address가 직접 같은 숫자가 아니다

D88 파일에서 어느 byte가 파일 offset 0x12345에 있다고 해서 게임 실행 중 RAM 2345h에 있다는 식의 직접 관계는 없습니다. 중간에 D88의 track/sector 구조, FDD read, SUB↔MAIN 전송, loader가 사용하는 destination address가 있기 때문입니다.

11-4. 2D와 2HD는 왜 모델 설명에 계속 등장하나

플로피의 기록 밀도와 용량이 다른 disk 규격이기 때문입니다. 초기/보급형은 2D 중심이고 MR/MH/MA 같은 M 계열에서는 2D/2HD drive를 기본으로 갖는 경우가 많습니다. NEC 공식 사양에서도 MR/MH/MA는 5인치 2D/2HD ×2로 기록됩니다.

분석에서 중요: 어떤 disk image를 어느 machine mode에서 부팅하는지, emulator가 2D/2HD를 어떻게 처리하는지는 loader 추적 전에 확인해야 합니다. 디스크 형식 자체는 3부 D88 편에서 자세히 배웁니다.

11-5. 게임 분석에서 SUB CPU breakpoint가 필요한 이유

나중에 debugger를 사용하다 보면 Main CPU의 loader code만으로 data 이동의 모든 원인을 설명하기 어려울 수 있습니다. 실제 disk read가 SUB CPU 쪽에서 진행되고 Main↔SUB handshake가 있기 때문입니다. 따라서 “디스크에서 이 data가 언제 읽혔는가”를 끝까지 추적하려면 SUB CPU 실행 위치와 interface 상태가 단서가 될 수 있습니다.

1부의 목표: SUB CPU의 명령어를 지금 외우는 것이 아닙니다. “disk read 경로에는 Main CPU 밖의 별도 subsystem이 끼어 있다”는 구조를 먼저 머릿속에 넣는 것이 목적입니다.

확인 문제

Q1. PC-8801의 표준 RAM 64KB와 Z80 주소 공간 64KiB는 같은 의미인가?
아닙니다. 표준 RAM 64KB는 실제 장착된 Main RAM의 용량이고, Z80의 64KiB 주소 공간은 CPU가 16bit address로 한 번에 표현하는 논리 주소 범위입니다. 후기에는 물리 RAM이 더 많아져도 Z80 주소 범위 자체는 그대로입니다.
Q2. M 계열의 192KB RAM은 Z80에서 00000h~2FFFFh처럼 연속으로 보이는가?
아닙니다. 64KB Main RAM + 128KB Expanded RAM으로 이해해야 합니다. Expanded RAM은 32KB bank 단위로 선택해 CPU 주소 0000h~7FFFh에 연결합니다.
Q3. Expanded RAM이 왜 32KB 단위인가?
PC-88 Expanded RAM 하드웨어가 CPU 주소 0000h~7FFFh를 bank window로 사용하기 때문입니다. 이 범위는 0x8000 byte, 즉 32KiB입니다. 128KB Expanded RAM은 그래서 32KB × 4 bank가 됩니다.
Q4. 같은 CPU 주소 2000h를 읽었는데 data가 달라질 수 있는 이유는?
현재 mapping이나 Expanded RAM bank가 달라졌을 수 있습니다. 2000h라는 논리 주소 뒤에 ROM, Main RAM, Expanded RAM 중 무엇이 연결됐는지를 함께 봐야 합니다.
Q5. Text Window와 Text VRAM은 같은 것인가?
아닙니다. Text Window는 Main RAM의 선택된 1KB를 8000h~83FFh에서 접근하기 위한 memory window입니다. Text VRAM/High-speed TVRAM은 화면 텍스트 처리 쪽의 메모리입니다.
Q6. GVRAM 48KB는 왜 48KB인가?
대표적인 컬러 그래픽 구조에서 Blue, Red, Green plane이 각각 약 16KB이고, 세 plane을 합치면 48KB이기 때문입니다.
Q7. 화면에 일본어 글자가 보이면 그 문자 code가 GVRAM에 그대로 들어 있는가?
반드시 그렇지 않습니다. 게임이 문자 code를 KANJI ROM이나 자체 font의 glyph bitmap으로 바꾼 뒤 GVRAM에 점 그림으로 그렸을 수 있습니다.
Q8. MA의 Sound RAM 256KB는 Main RAM에 포함되는가?
아닙니다. ADPCM 등 sound 기능을 위한 별도 메모리입니다. Main/Expanded RAM과 용도와 접근 방식이 다릅니다.
Q9. Main CPU가 D88의 sector data를 직접 읽는가?
그렇게 단순화하면 안 됩니다. PC-88의 5인치 FDD 계통에는 별도의 disk subsystem이 있고, SUB CPU/FDC가 실제 disk 작업을 처리한 뒤 Main 시스템과 interface를 통해 data를 주고받습니다.
Q10. PC-88 한글화에서 주소 하나만 기록하면 충분한가?
아닙니다. 특히 bank/mapping이 관련되면 CPU address뿐 아니라 당시 ROM/Main RAM 상태, Expanded RAM card/bank, GVRAM 접근 mode 등을 함께 기록해야 같은 data를 정확히 다시 찾을 수 있습니다.
